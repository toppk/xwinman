# xwinman.org on Hugo

The mirrored site (`mirror/xteddy.org/xwinman/`, untouched, local only and
gitignored: it was an intermediate representation, and `tools/verify.py`
needs it) is regenerated from a Hugo source tree. Each window manager is a
self-contained bundle: front matter + Markdown + its rc files, screenshots
and logo. The build republishes those files at the original `/rc/`,
`/screenshots/` and `/images/` URLs, so every old link keeps working.

## Layout

```
hugo.toml                   uglyURLs, permalinks, Goldmark settings, params.edition
layouts/_default/baseof.html  page chrome (head, logo, navbar, sidebar, footer)
layouts/wm/single.html        WM/desktop page; renders `members` in order with <hr> between
layouts/partials/wm-body.html logo header (three shapes), license box, body
layouts/partials/publish-resources.html  copies bundle files to their old site-wide paths
layouts/index.html          home page logo grid from the edition's home.toml
layouts/shortcodes/entries.html  renders an edition's Others list ({{< entries "wm-other" >}})
data/editions/latest/       the edition: nav.toml (sidebar groups, navbar, labels), home.toml
                            (logo grid rows), wm-other.toml and de-other.toml (ordered refs)
layouts/partials/autoindex-page.html  Apache 1.3 style directory listing page
layouts/partials/autoindex-dir.html  derives a listing from the files on disk (names, sizes, mtimes, icon and
                            description by extension) for every directory under collections/ and static/archive/
                            without an index.html, publishes <dir>/index.html, recurses. No data files, no stubs.
collections/                icons/, textures/, tiles/ unpacked from the Icons bundle archives
                            (generated by `migrate.py collections`, gitignored), mounted as static
static/archive/             the source archive, committed; each directory's _metadata.toml records the
                            original timestamps git cannot keep; `migrate.py collections` applies them before a build.
                            It is served with the archive (hidden from the listing), like a README would be
content/_index.md           home page welcome text
content/{intro,basics,feedback,notes,links,comparisons}.md
content/icons/              Icons page + icons.tar.gz, textures.tar.gz, tiles.zip
content/resource/           X Resources page + rc/Xresources
content/wm/<name>/          index.md (identity + prose), <logo>.*, rc/, screenshots/,
                            _metadata.toml (describes the files: who, when, which), links.toml
content/desktop/<name>/     same shape (type: wm)
content/wm/others/ content/desktop/otherdesktops/   list pages (type: page); intro/outro prose plus the shortcode
content/wm/<stub>/index.md  one stub bundle per Others entry: title, homepage, blurb (Markdown),
                            build.render never, so no page and no nav until it grows content
static/                     style.css, chart.gif, site-wide images
tools/migrate.py            mirror -> content (rerunnable; deletes content/ first)
tools/verify.py             public/ vs mirror check
```

Content is Markdown. pandoc converts the old HTML; constructs Markdown cannot
express are kept as raw HTML: `<table>`, `<pre>`, `<kbd>`, `<font>`, `<hr>`,
`<a name>`, empty `<p>` before a block (it changes spacing, and table font
size), and `<br>` runs between blocks. The template emits the logo header and
the license/activity box from front matter.

### Front matter (example: fvwm)

```yaml
title: FVWM
build: {publishResources: false}      # publish-resources.html places files instead
logo_sm: {file: fvwm_sm.png, alt: fvwm, width: 105, height: 35}   # home grid
logo:    {file: fvwm.png, alt: "[LOGO]", width: 250, height: 83}
heading: Tab Window Manager            # optional; heading_style: table for the 2-cell layout
heading_sep: '&nbsp; '                 # exact spacing between logo and heading
license: GPL                           # license_note: "(Open Motif)" when present
activity: High
```

Front matter is identity only. What describes the files in a directory is
`_metadata.toml`, one shape everywhere, in the spirit of Apache's
`AddDescription`: each `[[entry]]` names files and records what is known
about them. In a bundle that is the contribution; the contribution list is
one view of it, an annotated directory listing could be another. In
`static/archive/` every directory has one, giving the original mtime of each
child (the root's also names `"."` for itself).

```toml
[[entry]]                        # content/wm/fvwm/_metadata.toml
files = ["rc/fvwmrc-matt", "screenshots/fvwm-matt.gif"]
from = "matt@belgarath.org"      # lead = "Another from" when the site said that
added = "1996-06"                # printed as "June 1996"
text = "[fvwmrc,](rc/fvwmrc-matt) [screenshot](screenshots/fvwm-matt.gif) (118k)."
# list = 2 when a page has more than one such list ({{< contributions 2 >}})

[[entry]]                        # static/archive/9wm/_metadata.toml
files = ["9wm-1.0.shar.Z"]
mtime = 1996-02-09T00:00:00+00:00
```

`links.toml` holds related sites as `[[link]]` name/url/blurb for
`{{< links >}}`. Shortcodes read both with `.Resources.Get` and
`transform.Unmarshal`; the lint in `tools/verify.py` checks every file under
`rc/` and `screenshots/` is described.

Entries whose sentence did not follow "From X, added in Month Year:" (12 of
100, e.g. "From the 1.0 release (97k) added in August 1998.") keep the whole
sentence in `text` and only what could be parsed as fields.

Other pages carry their tables the same way: `comparisons.md` has `features`
(columns as lines, rows with `has` booleans) and `resources` (rows with
`values`), rendered by `{{< features >}}` and `{{< resources >}}`; `links.md`
has titled `groups` of Markdown items for `{{< linkgroups >}}`. The Notes
page's two vocabularies, which every bundle's `license` and `activity` field
names, live in `data/licenses.toml` and `data/activity.toml` and are
rendered by `{{< licenses osi >}}`, `{{< licenses other >}}` and
`{{< activity-ratings >}}`. The only prose left is prose: introductions,
explanations, and the GNOME/KDE news tables, which are frozen 2006 feed
snapshots kept as raw HTML.

Sibling window managers share a page: `content/wm/vtwm/index.md` has
`members: [twm, vtwm]`; `content/wm/twm/` is a full bundle of its own with
`build: {render: never, list: never}`. Same for olwm/olvwm.

## Verification

`hugo && python3 tools/verify.py`:

- non-HTML files must be byte-identical to the mirror;
- HTML pages are compared as a canonical stream (text with collapsed
  whitespace, links, images with dimensions, headings, lists, tables, kbd,
  emphasis), which ignores unclosed/closed `<p>` and whitespace;
- a lint checks every `rc/` and `screenshots/` file in a bundle is referenced
  from its body and listed in `contributions`.

A pixel comparison (headless Chrome screenshots at 1100x1400, mirror vs
public) was also run on 2026-09-05: 28 of 32 pages identical. Known
differences:

- afterstep.html: the original serves a UTF-8 `®` as ISO-8859-1 (`Â®`); the
  site is now UTF-8, so it renders correctly and one paragraph reflows.
- notes.html: a stray `</p>` inside the license list gave the original an
  extra gap after the first item.
- fvwm.html, metacity.html: sub-pixel differences from a trailing space inside
  a link.

Typos in the original HTML that were corrected because they broke the
conversion: `Flowe Desktop:</a>`, `these icons.<a>`, `themes.org)/a>`, a
missing `>` on the comp.windows.x link, and a missing `</ul>` on
otherdesktops.html. One deliberate edit: the Icons page's `icons/index.html`
link now says `icons/`, like its `textures/` and `tiles/` neighbours.

## Decisions (2026-09-05)

1. Verification target is DOM-approximate, not byte-identical.
2. Sibling window managers stay as `members` of one page; wm2/wmx is one
   bundle whose sidebar label is "wm2/wmx".
3. `contributions` is data and is what the page renders; the sentence after
   the lead-in is its `text` field. Related links, the comparison tables,
   the Links page groups and the Notes vocabularies are data too (2026-09-05).
4. The mirrored `icons/` directory (Apache's default icons, served by
   xteddy.org for a link that expected the XPM collection) and `robots.txt`
   were deleted from the mirror. Wayback Machine listings confirmed that
   `icons.tar.gz`, `textures.tar.gz` and `tiles.zip` hold exactly what the
   three browsable directories served (tiles.zip even includes the Apache
   HEADER/README text and the per-size gallery pages), so `tools/migrate.py`
   unpacks them into `collections/` and writes Apache 1.3 style listings
   (names, sizes, archive timestamps in UK local time) using four icons kept
   from the Apache set in `static/images/apache/`.
5. The source archive (`archive/`, 44 subdirectories) was mirrored from the
   Wayback Machine into `mirror/archive/` (with `manifest.tsv` recording the
   captures). `tools/migrate.py` copies it into `collections/archive/` and
   parses the mirrored Apache index pages for the original names, dates,
   sizes and descriptions, so the generated listings match the old ones.
   Listings are derived from the files at build time, in `TZ=Europe/London`
   (the original server's clock; Hugo cannot convert zones in templates).
   Five tarballs are corrupt in every Wayback capture: two were replaced by
   the upstream releases (recorded as `source` in their `_metadata.toml`),
   three are not preserved; one more was never captured. Both are listed in `docs/restoration.md`, which
   also records how the mirror and the archive were fetched.
6. `xpmicons.gif` and `screenshots/fluxbox-dbl.jpg` were recovered from
   Wayback captures of earlier hosts; every file the 2018 site references is
   now present (see `docs/restoration.md` and `docs/links.md`).
7. GitHub Pages via `.github/workflows/pages.yml`: unpack collections, `hugo`,
   deploy. All links are relative so the path prefix does not matter. The
   mirror is not in the repo, so the verifier is a local tool only.
